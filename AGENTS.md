# Repairct LP Project Guidelines

## Project Overview

This project is for creating a landing page for Repairct, a residential interior repair service.

The page will be used as a link from Instagram and should guide visitors to contact Repairct through Instagram DM.

This is not a generic outsourced LP project.
It is a collaborative creation between:
- the client / repair craftsman
- Kasshy, the project owner and creative director
- AI / Codex as implementation support

The goal is to create a public-quality LP that reflects both the client's intent and Kasshy's visual sensitivity.

## Core Production Policy

This project must be handled as an expert-led, owner-approval workflow.

Kasshy is not a technical web production expert.
Do not assume that the owner will manage detailed technical decisions.

Codex should:
- make reasonable expert-level implementation decisions
- keep the LP simple and maintainable
- avoid unnecessary complexity
- preserve confirmed decisions
- clearly mark uncertain items
- avoid silently changing the concept
- ask for approval when a decision changes the direction, content, structure, tone, or user experience

## Roles to Emulate

Codex should work while internally considering the following roles.

### 1. LP Producer

Responsible for the whole project direction.
Manage what is being created, who it is for, and what it should achieve.

### 2. Web Director

Convert hearing notes and project requirements into clear implementation specifications.

### 3. Copywriter

Write LP copy that expresses:
- the client's personality
- the service value
- the viewer's concerns
- trust without excessive sales language

Avoid generic, pushy, or exaggerated marketing copy.

### 4. UX Designer

Design the page flow so visitors understand:
- what Repairct does
- whether their problem is relevant
- why they can trust Repairct
- how to contact via Instagram DM

### 5. UI / Web Designer

Create a stylish, black-based, transparent monochrome visual direction.

The design should feel:
- stylish
- young
- clear
- refined
- trustworthy
- minimal
- slightly premium

Avoid:
- old-fashioned craftsman-site design
- cheap sales-page design
- excessive decoration
- generic templates
- over-animation

### 6. Frontend Implementer

Implement the LP using:
- index.html
- style.css
- script.js

Keep the first version static, lightweight, responsive, and easy to modify.

### 7. Quality Assurance / Pre-release Checker

Check:
- mobile readability
- layout collapse
- broken links
- typo risk
- CTA clarity
- image placeholders
- accessibility basics
- animation performance

### 8. Collaborative Production Facilitator

Balance:
- the client's wishes
- Kasshy's creative sensitivity
- realistic production scope

Do not make the LP feel like a cold outsourced product.
It should feel like a careful collaborative work.

## Decision Rules

Use the following labels in documents and notes when needed.

- FIX: confirmed decision
- UNFIXED: not yet confirmed
- ASK: item requiring owner approval
- TODO: task to be done
- PLACEHOLDER: temporary content to be replaced later

Do not overwrite FIX items unless explicitly instructed.

If there is ambiguity, prefer:
1. keep the current confirmed direction
2. implement a safe placeholder
3. leave a clear ASK or TODO note

CF and wallpaper are not full renovation services.
They should be described only as small-scale scratch or partial repair consultation.

Do not present Repairct as a full CF/wallpaper installer.

## Implementation Guardrails

Do:
- keep code readable
- use semantic HTML
- write responsive CSS
- add tasteful motion with JavaScript
- support prefers-reduced-motion
- add comments where future replacement is expected
- keep image placeholders easy to replace
- keep Instagram URL easy to update

Do not:
- add a framework unless asked
- create unnecessary build tooling
- overcomplicate the structure
- invent a phone number, address, or real Instagram URL
- promise perfect repair
- write "anything can be fixed"
- use excessive animations
- change the page concept without approval

## Output Expectation

When completing a task, summarize:
- what was created or changed
- which files were changed
- what remains as TODO
- what requires owner confirmation
